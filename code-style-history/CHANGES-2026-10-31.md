## Structural changes

- **Decision log.** `references/decisions.md` records every contested question with the decision, the reasoning, the losing option, and the condition to reopen. `SKILL.md` directs the agent there before proposing a change or when a user questions a rule, and says a question settled there is not reversed on doubt alone. This is the mechanism against reopening the same questions every session.
- **Reasons on every principle.** Each principle opens with the failure it prevents. The agent is told that when the reason does not apply, the rule does not either, and to say so.
- **Working procedure.** `SKILL.md` step 3 names what to do before writing (unit of work, inputs, effects versus decisions, existing terms, each bad-input case). Step 6 asks for one line per judgment call made under a default. A new "When to stop and ask" section lists the four cases that pause: public contract, irreversible data change, a spreading repository-versus-guide conflict, scope growing past the ticket.
- **Code snippets in the skill.** Four, each ten lines or fewer, generic domain: the method-that-reads-nothing-from-self, chained defaults versus an envelope model, the iterator contract. Chosen because these are the patterns prose alone has not corrected. Longer examples are in the prose companion only.

## principles.md

- Principle 1 adds Carmack's continuum ("moving toward purity helps before reaching it; the worst code first"), the warning against a single bag of everything passed into logic, the general shape rule (data types plus functions; a workflow is a function), and Bowers's medium-scale point (plain loops in pure functions are already functional; comprehension chains and pipeline libraries for sequencing are not the lesson).
- Principle 2 keeps the 2026-10-30 reconciliation of fail-fast with define-errors-out-of-existence (one test: plausible but wrong value) and now cites Ousterhout's chapter.
- **New principle 3**, deterministic and rerun-safe units of work (Beauchemin): parameters in, replace-write out, one output, per-run scratch, immutable raw inputs, run every step every run (Carmack), date-gated logic, stated reason for self-dependence. Later principles renumbered; cross-references in both language files updated.
- Principle 5 adds Vaillant's declare-near-use and inline-a-once-used-variable, Bowers's no inner platform for sequencing, and Cheney's rule for comments on constants. Depth over decomposition now states the resolution of inline-versus-extract: a step several places must run is made pure and called from one place.
- Principle 7 adds a production-shape test (from the 2026-10-20 observed outcome) and a daylight-saving case for date logic.
- Principle 8 adds "a constructor does no I/O" (Carmack) and Bowers's interface normalization: one interface across differing sources with documented no-op implementations.
- Principle 9 opens with Bowers's "constrain, do not eliminate" and adds Carmack's value-returning variant and one-check-in-one-place.
- Principle 10 adds why layers help testing (a fake built from the fakes beneath).

## python.md

- "Data, functions, and classes" rewritten around the shape rule. New: the mechanical test for a method on a shell class (reads nothing from `self`: function; reads only settings: function taking them; chooses between effects: pure decision plus apply); a workflow is a function and collaborators may travel in a frozen dataclass; one snippet. Nested or chained comprehensions named as a smell.
- Module-level state rule added (constants and immutable tables only).
- Boundary snippet: chained `.get` defaults versus an envelope model.
- Exceptions: the define-away bullet is now generic (`not_found_ok`, `exists_ok` as examples, no vendor-specific text beyond that); custom exceptions carry the upstream code as a field.
- New "Pipelines" section: how principle 3 looks under any orchestrator.
- Tests: `match=` on the part of the message that carries the rule; a fake is a small class with real method names and a failure mode.
- Predicate and `_validate_`/`_check_` naming moved to Names.

## go.md

- Cheney added as a tagged source with the superseded parts listed in Sources and versions.
- Names: length by distance (Cheney's formulation), no mixing long and short in one list, `ctx` not `context`.
- Types: `var x T` versus `x := expr` as one line (Uber, Cheney).
- Functions: no test-only parameters on exported functions (Cheney).
- Errors: opaque beyond sentinels and types; never a nil pointer for "nothing happened"; handle once with Cheney's reasoning.
- Sequences: the `Seq2[T, error]` rule rewritten with the evidence (Google client libraries, Stripe, go-github), the contract to document, the honest caveat about single-variable ranges, and a seven-line snippet.
- Concurrency: buffers of zero or one (Cheney); `context` named beside `errgroup`.
- Comments: interface-implementing methods still get a real comment (departs from Cheney, with CRC and Google cited); constants' comments describe contents.
- Tests: `testify` is the default for new repositories, with the guardrails, marked as departing from TC and Google; standard-library repositories stay as they are. External tests by default, with the reasoning.

## Comparison runs

Six fresh subagents, three tasks, each task once under the installed 2026-10-29 skill and once under this draft, identical prompts. All outputs pass their checks (`ruff`, `pytest`, `gofmt`, `go vet`, `go test -race`). Files and the agents' own notes are in `scratch/code-style-examples-2026-10-31-fable-5.1/`. One run per cell cannot separate a rule's effect from run-to-run variance, so nothing below is treated as proof, and no rule was cut on this evidence.

**What the two guides produced in common.** On all three tasks the structure converged: functional core and shell, pydantic models at the boundary, fakes rather than mocks, `replace_partition` once after all pages are fetched, `run() error` plus one `os.Exit`, `iter.Seq2[Event, error]` for the paginated API. The last one is notable: the 2026-10-29 skill has no Sequences section, so the model chose `Seq2[T, error]` on its own prior. The house rule confirms a default the model already has, which is the right kind of house rule.

**Visible effects of the draft.**

- Go: `Range{From, To}` instead of `from, to time.Time` (the adjacent-parameters rule); tests in `auditexport_test` with the `cmd` tests in `main_internal_test.go` and an `Example` (the test-package rule); `testify` with `cmp.Diff` (the testify rule); a discarded decode error carries its comment (the `_` rule).
- Python, new module: the agent reported its judgment calls in a "calls that could go another way" list (SKILL.md step 6), which the old-skill agent did not.
- Python, real module: the agent stopped at the constructor's file read (`load_system_prompt()` in `__init__`) because fixing it changes a public contract, and flagged it instead of changing it (the stop-and-ask section). It extracted `_hooks` from a 120-line `_build_options` by the one-sentence test. Both agents moved `_observe` to module level.

**Where the old skill's output was at least as good.** The old-skill Python refactor extracted a pure `_decide_follow_up` returning a plan type, which the old `python.md` demanded in so many words ("a method that would branch two or more ways into different effects"); the draft states the same idea as a test on shell-class methods, and its agent left the three-way branch inline. The old agent itself doubted the extraction. The old Go output bounded the error body with `io.LimitReader` and distinguished a missing `events` field from an empty one; the draft's did not. The old pipeline used a `Literal`-discriminated union for the page, which prevents the invalid `ok: false` with no error more cleanly than the draft's `model_validator`.

**A judgment divergence to watch.** Given a line issued outside the requested day, the old-skill agent raised and the draft's agent dropped it with a logged count. Both are permitted by principle 2 ("skip it and log the skip"), and the draft's agent argued from the partition's contract. If this recurs, the define-away subsection may be biasing toward skipping, and the rule would need a sentence distinguishing "not this unit's concern" from "contradicts an assumption".

**Defect found in the draft.** The pipelines rule "name the function for what it leaves behind" produced a noun-named entry point (`invoice_lines_partition`), contradicting the verb rule in the same file. Fixed to "a verb and its output".

**Benchmark, first run.** `scratch/code-style-benchmark-2026-10-31-fable-5.1/` (seven tasks, hidden tests, AST pattern checks, validated against reference solutions). Seventeen runs across three tasks and the negative control, with no skill, the old skill, and the draft: every cell scored 100% on hidden tests with zero violations except one `pytest.raises(Exception)` in the no-skill webhook tests. The fixture scores 6/9 and 9 violations, so the benchmark separates good from bad; it does not separate these three variants on tasks of this size, because the model already does this work well unaided. Unscored differences: skilled runs moved logic to module functions and typed rows where the no-skill run kept methods and dicts; the draft's output was 8 to 19 percent shorter than the old skill's. One check was corrected (a clock read inside a parameter default is injection, not a hidden input). Next: harder tasks and structural columns, and the relay project as the discriminating test.

**On size.** The comparison cannot identify inert rules at one run per cell. A code-style benchmark (several runs per cell, hidden tests, mutation score, a negative-control task where a rule should not fire) is the way to earn cuts; the layout skills have one and this skill does not.
